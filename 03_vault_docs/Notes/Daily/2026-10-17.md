## 🔍 1. Investigasi & Akar Masalah Kegagalan Ekspor Foto PDSE, PTDS, dan PTLS

### Akar Masalah:
- **Deteksi Halaman Berbasis pypdf**: Pada file PDF checklist perawatan yang dibuat dengan TCPDF (seperti form PDSE, PTDS, PTLS), semua elemen gambar disematkan pada *Resources catalog* level dokumen/halaman awal. Perintah `len(reader.pages[i].images) >= 3` secara keliru mendeteksi Page 2 (lembar checklist tabel) sebagai halaman dokumentasi foto karena Page 2 mewarisi 4 resources gambar dari katalog, padahal Page 2 tidak merender foto apapun.
- **Dampak**: Halaman foto sesungguhnya (Page 3 untuk PDSE/PTDS atau Page 4 untuk PTLS) terlewatkan dan ekstraksi menghasilkan 0 foto.
- **Risiko Overwrite Multi-Inspeksi**: Beberapa aset PDSE/PTDS/PTLS memiliki jadwal perawatan lebih dari satu kali dalam sebulan (contoh: BTT tanggal 08-01-2026 dan 22-01-2026; BOO tanggal 05-01-2026 dan 08-01-2026). Jika nama folder tujuan hanya menggunakan nama aset (`BTT` atau `BOO`), inspeksi kedua akan menimpa (*overwrite*) foto inspeksi pertama.

### Solusi yang Diimplementasikan (`export_pdf_foto.py`):
1. **Deteksi Berbasis pdfplumber Image Placements**: Mengganti pengecekan resource `pypdf` dengan `page.images` dari `pdfplumber` yang membedah content stream penempatan elemen gambar riil di kanvas halaman.
2. **Fallback Otomatis**: Jika deteksi teks judul gagal menemukan halaman foto, sistem memindai seluruh halaman PDF dan memilih halaman yang memiliki $\ge 3$ penempatan citra nyata.
3. **Multi-Inspection Auto Suffix (`_DD-MM`)**: Sebelum ekstraksi, sistem mengaudit seluruh daftar file PDF dalam direktori yang sama. Jika terdeteksi stasiun/kategori/detail yang sama dengan tanggal berbeda dalam bulan yang sama, folder tujuan otomatis diberi akhiran tanggal (misal `BTT_08-01` dan `BTT_22-01`), mencegah timpa-menimpa file secara permanen.
4. **Verifikasi 100% (417/417 PDF)**: Seluruh 417 sampel PDF perawatan diuji secara menyeluruh dan 100% foto berhasil diekstrak dengan tepat.

## ⏱️ 5. Investigasi & Solusi: Mengapa Schedule PDSE, PTDS, dan PTLS Tidak Terbuat (v1.8.1)

### Akar Masalah:
1. **Efek Berantai Kegagalan Ekstraksi Foto (Step 1)**:
   - Sebelum v1.8.0, `export_pdf_foto.py` mengekstrak 0 foto untuk PDSE, PTDS, dan PTLS.
   - Karena folder foto tidak tercipta di `03_export_foto`, Step 2 (`extract_pdf_dates.py`) melewatkan folder tersebut, dan Step 4 (`edit_timemark_ide1.py`) mendeteksi 0 foto sehingga timemark tidak pernah diproses.
2. **Desinkronisasi Suffix Multi-Inspeksi (`_DD-MM`) pada `scheduler.py`**:
   - `export_pdf_foto.py` menghitung kemunculan berkas (`multi_date_lookup`) dan menambahkan suffix tanggal ke folder (misal `BTT_08-01`, `BTT_22-01`, `BOO_05-01`).
   - Namun `scheduler.py` sebelumnya hanya menambahkan suffix jika foldernya sudah ada di disk (`(photos_dir / ...).is_dir()`). Jika jadwal di-generate sebelum folder ada, entri jadwal bernama `BTT`, sehingga Step 4 dan Galeri gagal mencocokkan jadwal ke foto `BTT_08-01`.
3. **Path Konfigurasi Acuan Waktu di Backend Webview**:
   - Endpoint `/api/timemark/generate-schedule` sebelumnya mencari file `mapping.json` dan `data_acuan.json` (yang seharusnya bernama `asset_waktu_mapping.json` dan `data_acuan_tenaga_gabungan.json`).

### Solusi yang Diterapkan:
1. **Integrasi `multi_date_lookup` di `scheduler.py`**:
   - `build_schedule` kini melakukan pre-scan seluruh file PDF untuk menghitung frekuensi inspeksi dan menerapkan `date_suffix` secara deterministik pada kategori `WESEL`, `PDSE`, `PTDS`, dan `PTLS`.
2. **Perbaikan Path Acuan di `run_desktop_webview.py`**:
   - Path mapping durasi kini diarahkan ke `asset_waktu_mapping.json` dan `data_acuan_tenaga_gabungan.json`.
3. **Verifikasi Lengkap 28 File Target**:
   - Pengujian `build_schedule` pada folder `SIAP DI OCR` membuktikan 28/28 file PDSE, PTDS, dan PTLS terjadwal 100% sempurna dengan rentang jam kerja dinas yang tepat dan identifier yang sinkron dengan struktur folder foto.
4. **Kompilasi & Rilis v1.8.1**:
   - `SintelisUtility.exe` dikompilasi (264,709,605 bytes) dan diunggah ke `02_server_update` port 8085.

## 🚀 6. Penyelarasan Arsitektur Pipeline Timemark v1.8.2 (Implementasi RFC)

Berdasarkan **Catatan Kesiapan & Penyelarasan Teknis (RFC v1.8.1/v1.8.2)**, dilakukan perbaikan arsitektural menyeluruh pada 3 titik kunci:

### 1. Perluasan Early Binding Multi-Tanggal & Isolasi Berkas Hari Sama (`_part{n}`)
- **Berkas**: `export_pdf_foto.py`, `scheduler.py`, `merge_pdf_foto.py`.
- **Solusi**:
  - `multi_date_lookup` kini aktif serempak untuk `{"WESEL", "PDSE", "PTDS", "PTLS", "SINYAL", "AXC"}` baik pada alur single-row maupun multi-row (`export_multi_row`).
  - Jika terdapat berkas ceklis kedua di hari yang sama bertanda ` (2).pdf` (misal `PERAWATAN PTDS CLT 16-02-2026 (2).pdf`), sistem secara deterministik menambahkan suffix `_{DD-MM}_part2`.
  - `scheduler.py` membedakan slot waktu `CLT_16-02` dan `CLT_16-02_part2` sehingga jam kerja berlanjut secara kronologis tanpa tabrakan.
  - `merge_pdf_foto.py` mencari folder dengan expected suffix `_part2` untuk berkas `(2).pdf`.

### 2. Step 2 Stateless & Instan (`extract_pdf_dates.py`)
- **Solusi**:
  - Menghapus operasi fisik duplikasi/rename folder (`prepare_multi_date_folders`) yang sebelumnya membebani I/O dan memicu risiko penamaan bertingkat (`_08-01_08-01`).
  - Step 2 kini menjadi operasi stateless sub-detik yang murni memindai folder (termasuk folder bersuffix `_part{n}`) dan menuliskan `date.txt` lokal.

### 3. Sinkronisasi Antar Repositori
- Seluruh skrip inti (`export_pdf_foto.py`, `scheduler.py`, `merge_pdf_foto.py`, `extract_pdf_dates.py`) telah disinkronkan secara identik ke repositori `OCR-FOTO-P3STE/scripts/`.

### 4. Status Rilis v1.8.2
- **Biner**: `SintelisUtility.exe` dikompilasi dengan PyInstaller ke `02_server_update/`.
- **Versi Server**: `version.json` diperbarui ke `1.8.2` dengan changelog lengkap.
