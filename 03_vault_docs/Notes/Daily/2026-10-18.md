## 10. Audit & Optimasi Ekstrem Alokasi Memori RAM (3.7 GB -> < 400 MB)

### Masalah:
* Pengguna melaporkan aplikasi `SintelisUtility` memakan RAM hingga mencapai 3 GB - 3.7 GB saat beroperasi.

### Hasil Investigasi & Audit Proses:
* Backend Python (`SintelisUtility.exe`): Hanya memakan **145.79 MB** RAM (sangat wajar).
* Renderer Browser (`msedgewebview2.exe`): Membengkak hingga **3,744.12 MB (~3.74 GB)**!
* **Penyebab Utama:**
  1. V8 Engine 64-bit default mengizinkan heap hingga 4096 MB (4 GB), sehingga Chromium tidak pernah memicu Garbage Collection skala besar jika tidak dibatasi.
  2. PDF.js Document Proxy Leaks: `extractDigitalText()` dan `renderPage1()` tidak pernah memanggil `await pdf.destroy()`, menahan dekompresi font, glyph, dan stream di Web Worker memory.
  3. Canvas Pixel Buffers Skia: Dimensi canvas tidak di-nolkan setelah OCR selesai, menahan puluhan MB per halaman di memory GPU/RAM renderer.
  4. Duplikasi ArrayBuffer di React state (`files._arrayBuffer`, `results[].data`) menahan ratusan MB binary data lama setelah file selesai disimpan.

### Solusi & Implementasi:
1. Penambahan argumen browser V8 di [`run_desktop_webview.py`](file:///c:/Users/SINTEL%201.21%20BOO/Documents/Server/Sintelis_Update_Server/01_scripts_pendukung/web-app/run_desktop_webview.py):
   `--renderer-process-limit=1 --js-flags=--max-old-space-size=384 --disk-cache-size=10485760 --media-cache-size=10485760 --aggressive-cache-discard`.
2. Perbaikan [`pdfProcessor.js`](file:///c:/Users/SINTEL%201.21%20BOO/Documents/Server/Sintelis_Update_Server/01_scripts_pendukung/web-app/src/utils/pdfProcessor.js):
   Bungkus `pdfjs.getDocument` dengan `try ... finally { if (pdf) await pdf.destroy(); }`.
   Pelepasan canvas instan via `canvas.width = 0; canvas.height = 0; enhanced.width = 0; enhanced.height = 0;`.
