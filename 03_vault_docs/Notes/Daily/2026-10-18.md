## 🛠️ 1. Perbaikan Bug Ubah Personil & No. SC (v1.8.5)

### Akar Masalah:
* Saat pengguna mengubah personil pada berkas PDF di modul *Koreksi Dokumen / Ubah Personil*, terjadi eksepsi:
  `ValueError: Font 'dejavusans-bold' is unsupported`
* **Penyebab**: Fungsi penghitungan lebar teks `_calc_w` memanggil `fitz.get_text_length(txt, fontname="DejaVuSans-Bold")` secara langsung. PyMuPDF tidak mengenali font kustom tanpa objek `fitz.Font(fontfile=...)`.

### Solusi yang Diterapkan (`personnel_changer_engine.py`):
1. **Helper `_calc_w` Berbasis Fontfile Asli:**
   Menggunakan `fitz.Font(fontfile=font_file).text_length(txt, fontsize=fsize)` dengan fallback bertingkat ke `hebo` dan kalkulasi proporsional.
2. **Uji Validasi:** Berkas target `PERAWATAN CATU DAYA ER SINYAL BOP 09-02-2025.pdf` berhasil diubah personilnya secara in-place ke tim baru tanpa error.

## 🔍 2. Resolusi Otomatis Nama Berkas Arsip 2025 (v1.8.6)

### Akar Masalah:
* Pada dokumen fisik arsip tahun 2025:
  * **Maseng**: File dinamai `PERAWATAN SINYAL J12B MSG ...` (di lapangan masih memakai kode lama `J12B`). Namun pada master data aset, ID aset terdaftar adalah `J12`.
  * **Bogor**: File dinamai `PERAWATAN AXLE COUNTER ZP 41B BOO ...` (typo lama lapangan `ZP 41B`). Pada master aset terdaftar sebagai `ZP 41`.
* **Dampak**: Berkas terlempar ke daftar **Unmatched Files** (*"Tidak ada slot master aset yang sesuai pada periode ini"*), dan di saat bersamaan aset master `J12 MSG` serta `ZP 41 BOO` berstatus **KURANG 1**.

### Solusi yang Diterapkan:
1. **Bidirectional Alias Resolver di `masterAssets.js`:**
   * Di fungsi `matchFileToAsset`:
     * Jika `sigId === 'J12B'` dan `loc === 'MSG'`, otomatis dinormalisasi ke `J12`.
     * Jika `zId === 'ZP 41B'` dan `loc === 'BOO'`, otomatis dinormalisasi ke `ZP 41`.
   * Di fungsi matcher `idMatches(masterId, fileId, loc, category)`:
     * Disediakan resolusi alias dua arah sehingga pencocokan tetap valid baik master mencari `J12`/`J12B` maupun `ZP 41`/`ZP 41B`.
     * *Isolasi Keamanan:* Khusus `J12B`, aturan ini dibatasi ketat hanya untuk lokasi `MSG` sehingga stasiun `CLT` dan `BTT` (yang memang memiliki sinyal keluar `J12A` dan `J12B` terpisah) tidak terpengaruh.
2. **Sinkronisasi Engine Pendukung:**
   * `extract_pdf_dates.py`: Ditambahkan `"J12B MSG": "J12 MSG"` pada kamus `IDENTIFIER_EXCEPTIONS`.
   * `merge_pdf_foto.py`: Ditambahkan kandidat pencocokan `J12B MSG` $\leftrightarrow$ `J12 MSG`.
   * `export_pdf_foto.py`: Ditambahkan sanitasi segmen `J12B MSG` $\rightarrow$ `J12 MSG`.

## ✍️ 4. Presisi Tipografi Fitur Ganti Tanggal (v1.8.7)

### Akar Masalah:
* Penulisan teks tanggal baru pada [`date_changer_engine.py`](file:///c:/Users/SINTEL%201.21%20BOO/Documents/Server/Sintelis_Update_Server/01_scripts_pendukung/web-app/timemark_engine/date_changer_engine.py) sebelumnya di-hardcode memakai font bawaan `Helvetica-Bold`.
* Teks asli pada formulir P3STE (dihasilkan oleh TCPDF) menggunakan font embedded **`DejaVuSans-Bold`** ukuran **`7.2 pt`**.
* Akibatnya:
  1. Huruf tanggal baru terlihat lebih ramping/kurus (*condensed*) dan tidak senada dengan label `Tanggal :` di sebelahnya.
  2. Titik baseline Y menggunakan estimasi manual `(bbox.x0, bbox.y1 - 1.5)` sehingga posisi vertikal tanggal melayang/turun beberapa piksel dari baris tabel asli.
  3. Pada halaman foto, penghitungan lebar teks `Helvetica-Bold` membuat posisi tengah teks tanggal meleset beberapa piksel dari sumbu tengah halaman.

### Solusi yang Diterapkan (`date_changer_engine.py`):
1. **Helper Font Otentik `_get_date_font()`:**
   Mendeteksi berkas `DejaVuSans-Bold.ttf` asli secara dinamis (mendukung PyInstaller `_MEIPASS` maupun dev directory).
2. **Penguncian Baseline `origin` & Ukuran 7.2 pt:**
   Teks tanggal baru disisipkan tepat pada koordinat tipografi `origin` bawaan span asli:
   ```python
   font_name, font_file = _get_date_font()
   font_size = target_p1_span.get("size", 7.2)
   origin = target_p1_span.get("origin")
   insert_pos = origin if origin else (bbox.x0, bbox.y1 - 1.5)
   p1.insert_text(insert_pos, iso_date, fontsize=font_size, fontname=font_name, fontfile=font_file, color=(0, 0, 0))
   ```
3. **Perataan Tengah Presisi Halaman Foto:**
   Kalkulasi lebar teks `indo_date` menggunakan metrik glif asli `custom_font.text_length(indo_date, fontsize=7.2)` sehingga `center_x` persis di titik tengah kanvas halaman.
